## Qualified candidate and native security finding

The owner approved SQLx 0.9.0 and Tokio 1.53.3 with default features disabled:
SQLx `runtime-tokio`, `sqlite-bundled`, `migrate`. The broad `sqlite` umbrella,
macros, other database drivers, deserialize/load-extension and unlock-notify are
not enabled. The all-target lock can still contain unselected optional packages;
it is not the actual compiled target inventory.

SQLx's original highest permitted libsqlite3-sys 0.37.0 bundles SQLite 3.51.3.
Its C-source SHA3 matches the official release, but that release lacks the FTS5
fixes listed for CVE-2026-11822/11824 in the [SQLite advisory](https://sqlite.org/cves.html).
The documented attack needs hostile SQL/database input and FTS5; this does not
establish a remotely reachable Routira exploit. A successful RustSec check alone
does not audit bundled native C.

The owner separately approved qualification and conditional adoption of the
[upstream one-line constraint change](https://github.com/launchbadge/sqlx/commit/94aafe3a68884d923b0798a767c8d7f6cfda89d2).
The local driver permits libsqlite3-sys below 0.39 rather than below 0.38; the
lockfile resolves exactly 0.38.2, bundling SQLite 3.53.2. No driver Rust code changed.
Full license texts are restored from the exact release source because packaged
driver license files contain relative pointers. Provenance and fingerprints are
kept with the intended third-party source; local raw logs stay in `.setup/p1-03`.

The native 3.53.2 C source matches the [official release hash](https://sqlite.org/releaselog/3_53_2.html):
`44fd61b9f93b4155105cb2d80c957ae6c64a8b5bd6ed51a4992f0dbd438e4e11`.
This is an identity/fix-version check, not proof of absence of all native defects.

## Owner-approved implementation boundary

One writer, at most 64 queued operations, SQLite busy timeout 1 second and response
deadline 5 seconds. Overflow/timeout are explicit, without hidden retry. A response
lost during COMMIT may require rereading state; timeout does not guarantee rollback.

P1-03 stores public credential metadata and SecretRefId links only. Raw verifier or
token bytes cannot be written until P1-07's protected storage/key lifecycle exists.
Actual verification remains P3-07 and live scoped admission remains P4-01. Catalog
payload/import limits remain P2-07; storing a revision identity is not dataset approval.
Implementation, failure/permission tests, Linux CI and independent review remain open.

## Implementation review correction

All nine jobs of [run 38991270355](https://github.com/romanpodg/Routira/actions/runs/38991270355)
passed for `7f5cce34d32b3cf3889f09437ce63fc55093ba7e`: Linux ran 39 workspace
tests (12 storage) plus four compile-fail examples with default and no-default
features. Actual Codecov backend/planning patch checks succeeded. CodeScene
7994560 failed its new-code and critical-rule gates; this is not recorded as passed.

Independent read-only implementation review completed on that same head/base,
log `.setup/p1-03/codex-review-implementation.log`, exit 0, and found one serious
defect. SQLite can automatically roll back on SQLITE_FULL while SQLx retains a
nonzero transaction depth. Reusing that connection after a missing-revision read
can acknowledge a later save without durably committing it. The existing rollback
test checked prior data, not a subsequent acknowledged write across reopen.

The correction drains queued rollback with a worker barrier and verifies that
SQLx has no open transaction before acknowledging an operation. An inconsistent
connection closes the writer; queued/future commands receive Closed and require
explicit reopen, without retry. The original error is retained; an apparent
success on an inconsistent connection becomes Unavailable. A new in-memory actor
regression failed before the correction and passed afterward on Windows. The
Linux SQLITE_FULL test now also requires closing the damaged writer, explicit
reopen and persistence of a subsequent successful write across another reopen.
Windows six storage tests and workspace Clippy passed after the correction;
new exact-head Linux CI and independent re-review are required before merge.
